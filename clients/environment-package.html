環境構築 詳細

① Claude Code（VS Code 拡張）

クライアントさまの作業環境を Claude Code 中心 で組みます。

何をセットアップするか

  • VS Code に Claude Code 拡張をインストール
  • Anthropic アカウントとAPIキー登録（クライアントさま名義）
  • 既定の作業ディレクトリ設定（業務ごとに分割）
  • ターミナル統合（PowerShell / Bash 自動切替）

なぜVS Codeか

  • ファイル編集・コマンド実行・AIチャットが 1画面で完結
  • Git 連携・拡張機能が豊富
  • 業務データを ローカルPC に置けるので情報漏洩リスクが低い
  • マルチPC運用しやすい

業界・業種・ご担当者ごとに 専用CLAUDE.md を書き起こします。

④ .env / APIキー 集約設計

課題（よくあるトラブル）

  • 複数PCで作業する時、片方PCに .env が無くて APIキー使えない
  • プロジェクト別 .env が散らばって管理不能
  • バックアップが取れない

僕の解決策

~/.openai/config.env          ← OPENAI_API_KEY
~/.gemini/config.env          ← GEMINI_API_KEY
~/.youtube-api/config.env     ← YouTube Data API
~/.x-auto-posting/.env        ← X発信
~/.claude/channels/discord/.env ← Discord Bot
~/.{業界専用}/config.env       ← クライアントさま業界固有

→ 6つの中央ファイルだけ バックアップすれば全PCで動く構造

→ 1Password / Bitwarden で「中央ファイルの中身」を保管
→ 新PCではご主人様がメモ帳で開いて貼り付け → 完了

→ 詳細は実際の設計書 .claude/env-inventory.md を参照

① memory/ 自動ロード型ナレッジ

クライアントさまの 個性・声色・好み・過去事例 を、
AI（Claude）が 会話のたびに自動で読み込む 形に整理します。

memory/ の中身

memory/
├── MEMORY.md                       ← インデックス（最大200行）
├── user_profile.md                 ← クライアントさまの基本情報
├── feedback_voice.md               ← 声色・文体ルール
├── feedback_no_xxx.md              ← NGルール（やってはいけない事）
├── project_xxx.md                  ← 進行中プロジェクト
├── reference_xxx.md                ← 外部リソース（Linear / Slack 等）
└── ...

自動ロードの仕組み

  • VS Codeで Claude Code 起動するたびに MEMORY.md を読み込む
  • ご主人様の質問に応じて、関連する個別ファイルを参照
  • ご主人様が「これ覚えて」と言うと、私（Claude）が自動で新規memoryを作成

→ クライアントさまは 「これ覚えて」「これ忘れて」と言うだけ で、
　 AI秘書の記憶が育っていく。

② 部署別フォルダ構成

業務領域ごとに フォルダ分割 して、情報の動線を整理します。

例：100t農家のイチロウの場合

部署_YouTube動画/        ← 動画台本・撮影記録・編集ノート
部署_LP制作/             ← LP原稿・LPボード生成物
部署_UTAGEちゃん/        ← LINE配信・ファネル
部署_Substack/           ← 長文記事
部署_すらいどちゃん/      ← プレゼン用スライド
部署_サムネ設計/          ← YouTubeサムネ・X記事サムネ
部署_労務管理/            ← パートさん管理
部署_個別相談/            ← 個別相談 案件
部署_作業ログ/            ← 議事録・進捗

→ クライアントさま業界に合わせて 5〜10部署 設計します。

ルール

  • 部署フォルダ直下には README.md を置く（その部署の運用ルール）
  • 案件ごとに 日付＋プロジェクト名 のサブフォルダ
  • 完了案件は archive/ に移動

③ knowledge/ 業務ナレッジ

商品・顧客・業界の 不変ナレッジ をここに集約。

中身の例

knowledge/
├── products/                       ← 商品ごと 1ファイル
│   ├── basic_19000.md
│   ├── industry_98000.md
│   └── pro_300000.md
├── customer-personas/              ← 顧客ペルソナ
├── industry-knowledge/             ← 業界の常識・トレンド
└── funnel-plan.md                  ← 商品間の関係性 一元化

重要ルール

  • 1商品 1ファイル（混ぜない）
  • 商品間の関係性は funnel-plan.md に集約
  • 商品ファイルに他商品の情報を混ぜると、AI混乱の原因

→ これは僕が農場経営で「キャベツ・白菜・人参を別ファイル管理」で
　 学んだ教訓を、商品ナレッジに適用したもの。

② 新規スキル設計フロー（クライアントさま業界特化）

クライアントさまの業務に合わせて オリジナルスキル を作る5ステップ：

Step 1：業務棚卸し（30分zoom）

「毎日・毎週・毎月、何度も繰り返す業務」を5〜10個リストアップ。
各業務について：
- 入力（何を見て）
- 加工（どう変換して）
- 出力（何を作るか）

Step 2：自動化候補の絞り込み

「これがAIに渡せたら楽」な3〜5個を選定。
基準：
- 頻度が高い（週1以上）
- 形式が定型（プロンプトに落とせる）
- 失敗してもリカバリー可能

Step 3：スキル仕様書 作成

各スキルに対して：

name: skill-name
description: 何をするか
inputs: 何を受け取るか
processing: 何を行うか
outputs: 何を出すか
triggers: いつ起動するか

Step 4：実装＋テスト

僕が実装＋セルフテスト＋クライアントさまレビュー。

Step 5：本番投入＋運用ドキュメント

クライアントさま用 README に「使い方・トラブルシュート・改善ポイント」を整理。

③ スキル設計の哲学

僕がスキルを作る時の 3原則：

1. 「0秒で今すぐ使える」状態で渡す

クライアントさまが受け取って、勉強しなくても使える こと。
チュートリアル不要、起動コマンド1個で完結。

2. 「クライアントさま自身が育てられる」設計

僕がいなくなっても、クライアントさま本人が修正・拡張できるように：
- スキルファイルは Markdown（プログラミング不要）
- 起動条件は自然言語のキーワード
- ナレッジファイルは平易な日本語

3. 「他のスキルと連携できる」設計

単体で完結するのではなく、 連鎖 できる：
- gijiroku-chan → learn-share → utage-step-writer のように
- スキル同士の入出力を Markdown ファイルでつなぐ

④ 学習＋発信の自動化（/learn-share コマンド）

クライアントさまが学んだこと（外部講義・読書・対話）を
48時間以内に X投稿 + LINE配信 + ブログ の3形態に加工する
スラッシュコマンドも提供します。

/learn-share <音声 or URL or テキスト>
  ↓
  Phase 1: 取り込み（whisperで文字起こし）
  Phase 2: 学びの抽出（5項目）
  Phase 3: 3形態生成（X / LINE / Substack）
  Phase 4: 自動投稿準備（オプション）
  Phase 5: 48時間期限管理

→ クライアントさまの 発信頻度 が劇的に上がります。
　 学び→放置 のループから抜け出せる。
